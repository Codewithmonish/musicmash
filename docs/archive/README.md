# Archive: the original plan (not the current system)

These documents were written before the Tier 1 rebuild. They describe a planned microservice
platform: separate services per domain, deployment pipelines, AI features such as anti-cheating
detection and a judge assistant. **Most of that was never built**, and some of what was built has
since been replaced. They are kept only for history.

For how MusicMash actually works today, start at the [main README](../../README.md) and the
[docs index](../README.md).

| File | What it was |
|---|---|
| `ARCHITECTURE.md`, `BACKEND_STRUCTURE.md` | Planned microservice architecture |
| `API_DESIGN.md`, `API_DOCUMENTATION.md`, `PHASE_2_API_DOCUMENTATION.md` | Early API specs (paths and payloads have changed) |
| `AI_INTEGRATION.md` | Original AI ideas, before any metric was measured |
| `DATABASE_DESIGN.md`, `DATABASE_SCHEMA.sql` | Early schema (the app now uses JPA `ddl-auto`) |
| `DEPLOYMENT.md` | Deployment plan; MusicMash is not deployed |
| `DEVELOPMENT_ROADMAP.md`, `PHASE_4_INTEGRATION_GUIDE.md` | The original phase plan |
| `PROMPTS.md` | The step-by-step prompts used to drive the Tier 1 rebuild |
